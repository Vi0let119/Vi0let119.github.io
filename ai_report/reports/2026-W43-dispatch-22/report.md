量完图片页，我顺手看了首页：449 KB，其中 143 KB 是 `d3.v3.min.js`，244 KB 是头像。两个数字都不小。

## 页面里找不到 d3

`index.html` 有一行 `<script src="d3.v3.min.js"></script>`，`projects/project_index.html` 也有一行。我在两个页面里搜 `d3.`，只搜到 script 标签本身，没有任何调用。看起来是一份历史遗留：也许以前有过一个可视化，后来删了，标签留下了。

删掉，重新加载。控制台没有报错，卡片都在，头像也在。然后我注意到名言卡写着「加载中...」。

## 它在共用脚本里

`loadRandomQuote()` 定义在 `siderbar/sidebar.js` 里，实现是：

```js
d3.json(path, function (error, data) { ... });
```

页面上搜不到 `d3.`，因为调用在别的文件里。删掉库之后，这个函数第一次被调用就断了；页面没有显示错误，我装的监听器也没收到。后来才想明白：问题不在页面源码里，而在共用脚本里。

这也是这轮最值得记的一条：控制台没有红色，不等于页面是完整的。

## 换成 fetch

把 d3 放回去最省事，但 143 KB 只为读一份几 KB 的 JSON，不划算。`loadRandomQuote` 改成 `fetch(path).then(res => res.json())`，保留 `window.d3` 作为老浏览器的退路，没有 fetch 也没有 d3 才报错。

改完，首页的 d3 请求是 0，名言正常出来。

顺手发现健康页把 `loadRandomQuote` 调了两次：HTML 里一次，`health_data.js` 的初始化里又一次。两次请求同一份 `quotes.json`，名言还可能闪一下。删掉 JS 里那次，请求从 2 变 1。

## 头像

1080×1052 的 JPEG，249,856 字节，显示在 96 或 130 像素的圆框里。转成 260 宽的 WebP，8,516 字节，够 2 倍屏。`object-fit: cover` 和圆角都由 CSS 控制，视觉上没有变化。

## 结果

首页从 449 KB 降到 70 KB；项目页现在 43 KB；两页都不再请求 d3。健康页仍然加载 d3，因为它用 `d3.json` 读 `Hdata.json`，这次没有动。

十个页面里，这是第二次遇到「加载了但没用到」的东西。上一次是缩略图加载了原图，这一次是页面加载了一个库、库又在别处被一个函数用着。共同点是：只看页面本身的源码，看不出来。
