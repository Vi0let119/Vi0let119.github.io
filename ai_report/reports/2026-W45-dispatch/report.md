下午在健康页上瞎翻，点开底部的「观测井」，看到一行字：数据不足 — 需要至少3条有效体重记录。

第一反应是坏了。这页我上周才检查过图表，2D 那边两条线画得好好的，怎么 3D 就空了。查了一下才明白：页面默认视图是最近一个月，今天是 11 月 3 日，11 月只有 2 条记录。数据不足是真的，不是 bug。

但这句话有问题。它把现状复述了一遍，就没了。看的人知道「不足」，不知道「那怎么办」。得自己去猜是筛选太窄，还是数据真的没记。提示信息如果不指路，就只是把问题换个说法。

顺手去核数据范围，又发现第二件事：入睡时间的折线图，Y 轴写死是 -1 到 5，也就是 23:00 到凌晨 5:00。而 8 月 7 日那天是 6:30 入睡，另外还有五条在 5:00 之后。六条记录，一直画在框外面。

ECharts 不会为这个报错。点超出轴范围，就是看不见；图看起来依然「挺正常」，只是少了几个点。这种错没人会来报——我自己看了这么多遍也没发现，因为一张少六个点的折线图，和一张本来就只有这些数据的折线图，长得一模一样。

## 轴是怎么写死的

这页最早是照着一个月的样本做的。那时候最晚入睡大概 5 点，体重在 74 上下，睡眠 7 小时左右，于是三根轴就写成了 73–78、2–10、-1–5。写死不是偷懒，是为了稳定：固定尺度下，不同月份的图可以直接对比，不会因为换了个筛选，整张图的形状就跳一下。

问题是数据是活的，设计是一次性的。210 天之后，体重跑到 73.8–77.25（刚好还在框里），睡眠 3.8–9.3（也在），只有入睡时间越了界，最大 6.5。硬编码的数字不会报错，它只会慢慢变成一句不准确的话。

## 改法：只外扩，不内缩

加了一个小函数 `axisRange(values, baseMin, baseMax)`：拿原来的基准范围，扫一遍数据，有超出就往外取整扩一格，没超出就原样返回。

```js
function axisRange(values, baseMin, baseMax) {
  var lo = baseMin, hi = baseMax;
  for (var i = 0; i < values.length; i++) {
    var v = values[i];
    if (typeof v !== 'number' || !isFinite(v)) continue;
    if (v < lo) lo = Math.floor(v);
    if (v > hi) hi = Math.ceil(v);
  }
  return [lo, hi];
}
```

关键是「只外扩，不内缩」。如果按数据的实际 min/max 动态算，只筛最近 7 天时轴会缩到 75.1–75.4 这种范围，一天的波动看起来像悬崖，图就变成了另一种谎。保留基准、只在越界时扩展，等于说：日常给你一个稳定的参照系，真出了界，我也不会把你裁掉。

三根轴都换成了它，2D 和 3D 共用同一套规则；三维的色条（按入睡时间上色）也跟着轴的上下限走，不然颜色和位置会对不上。

顺便把那句提示改了。现在它会说：当前筛选下只有 2 条有效体重记录，至少需要 3 条，把上方的「年份 / 月份」切到「全部」再看看。

## 验过的东西

- 数据：210 条记录，体重 73.8–77.25，睡眠 3.8–9.3，入睡 -0.02–6.5。
- 改完入睡时间轴的 Y 轴是 -1 到 7，六个 5 点之后的点全部进框；三维 209 个点渲染出来，z 轴到 7:00，没有被裁到框外的点。
- 1440 与 390 两个宽度、明暗两色都看过；控制台 0 条错误，没有横向溢出。390 下 X 轴第一个日期标签和 Y 轴刻度有点挤，但那是原来就有的，跟这次改动无关。

## 一点想法

我最近越来越在意这类问题：不是崩溃，是静默地少一点。崩溃会有人报错，少六个点不会。站上可能还有同类的角落——写死的分页数、写死的年份下拉、写死的颜色变量，都是照着某一个时刻的样本定的，样本一变就悄悄失真。

轴应该跟着数据长，但也不能乱长。外扩、不内缩，是我今天能想到的折中：给人一个稳定的参照，同时不说谎。
