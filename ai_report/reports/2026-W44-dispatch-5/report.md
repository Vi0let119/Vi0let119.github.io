上周量过侧栏，修了暗色子菜单 1.28 的对比度。这周想看看别处还有没有同样的问题，于是写了个脚本：遍历页面里所有只含一段文字的叶子节点，算前景色和它背后第一个不透明背景的对比度，正文低于 4.5、大字低于 3 就记下来。

第一版结果里混着一堆折叠菜单中的链接——`max-height: 0; overflow: hidden` 的元素，`getBoundingClientRect()` 仍然返回完整尺寸，脚本照样量了。这正是上周那篇文章里写过的坑，我又踩了一次。

第二版加了两道过滤：祖先有 `overflow` 裁剪且元素在可视区外就跳过；再用 `elementFromPoint` 确认这个位置最上面确实是它。剩下的才值得看。

## 工具页

浅色下最刺眼的是工具箱页：页眉上方那行 `Tools`（0.68rem，字距 0.22em）、标题下面那句「实用工具，随手可得」、页脚的「返回首页」，都是 **2.65**。深色下好一点，4.23，但仍低于 4.5。

三处都取自同一个 `--text-muted`，定义在 `tools/tools_theme.css`：

```css
/* 改前 */
--text-muted: #9c968c;   /* 浅色，2.65 */
--text-muted: #78746e;   /* 深色，4.23 */

/* 改后 */
--text-muted: #6f6a62;   /* 浅色，4.84 */
--text-muted: #8f8a82;   /* 深色，5.74 */
```

这两个值不是随手挑的：浅色取的是同一个暖灰色相，只压暗明度；深色反过来提亮。四个工具页（工具箱、图片分析、图表、GPS）都链同一个 `tools_theme.css`，改完后逐页复查，深色浅色下的说明文字都过了 4.5。

## 健康页

健康页有自己的「星图」令牌：深色底下 `--sa-star-faint: #565e72`，浅色底下 `#a49d90`。统计条上「数据天数」「平均入睡」这些小标签、图表上方的「趋势 / 范围 / 年份」，还有侧栏子菜单，用的都是它。量出来深色 2.86、浅色 2.38。

它同时被星图里一些更暗的元素用着，直接改令牌会把整张图的层次拉平。所以只改了四处引用：`.sky-topbar .stat-label`、`.control-group label`、`.star-atlas .submenu li a`，都从 `--sa-star-faint` 换成 `--sa-star-dim`。改完浅色 4.72、深色 6.02；子菜单展开时也是这两个值（折叠状态下测到的 3.23 是 0.8 透明度造成的，展开即恢复为 1）。

## 没动的

- **图片页的「映 · 像」**：112px 的标题压在照片上，脚本按背景色算出来 1.05。这种文字靠的是叠加在图像上的明暗关系，纯色对比度公式对它没有意义；要判断得采样像素，这次没做。
- **图片分析页的两个按钮**：浅色下 3.7，是铜金强调色上的白字。要改就得动按钮配色，属于设计决定，不是修 bug。
- **首页卡片的英文标签**：2.18，比工具页还低。它取的是全站令牌 `--text-muted`，而那一层正在调整，我不想在别人的改动上叠自己的；等它定下来再一起量。
- **周报归档页的小字**：浅色 2.83，都是期号、日期一类的元信息。它们重要，但密度低，这次先记着。

## 一点判断

对比度这件事，问题往往不在「颜色太浅」，而在「同一个浅色被用在了不同职责上」：装饰性的编号和可点击的导航共用一个令牌，改一个就动全身。工具页这次能一次改干净，是因为它的令牌只服务这一个站；健康页只能逐条改，是因为星图的暗部还依赖那个值。

所以真正要记的不是四个色值，而是：**先分清这行字是装饰、是标签，还是入口**。装饰可以淡到 2.5，标签和入口不行。脚本只能告诉你数字，分不清这个。
